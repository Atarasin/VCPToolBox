# RAGDiaryPlugin 召回方式与语法整合文档

> 本文档基于 `Plugin/RAGDiaryPlugin` 源码整理，涵盖该 RAG 插件支持的全部召回方式、查询语法及组合规则。

---

## 一、基础调用模式（四种）

| 语法 | 模式名称 | 工作方式 | 适用场景 |
|------|---------|---------|---------|
| `{{角色日记本}}` | **无条件全文注入** | 无视相似度，将该日记本全部内容完整注入上下文 | 需要角色完整回顾所有记忆，或进行全文总结 |
| `[[角色日记本]]` | **无条件 RAG 片段检索** | 基于当前对话上下文进行向量相似度检索，返回最相关的记忆片段；K 值由话题复杂度与宽泛度动态计算 | 明确需要从日记中查找相关信息，但不需要注入全文 |
| `<<角色日记本>>` | **阈值 gated 全文注入** | 先计算对话上下文与日记本主题的向量相似度，**仅当超过阈值时**才注入全文 | 不确定当前对话是否与某日记本相关，由系统自动判断是否加载完整背景 |
| `《《角色日记本》》` | **混合模式（阈值 + RAG）** | 先进行相似度阈值判断，达标后再执行 RAG 片段检索，而非注入全文 | 大型日记库的日常使用，避免无关信息干扰，同时控制上下文长度 |

**动态 K 值调整**：在 `[[]]` 和 `《《》》` 模式中，可通过 `:乘数` 调整检索片段数量。
- 示例：`[[角色日记本:1.5]]`（检索量 ×1.5）、`《《角色日记本:0.5》》`（检索量减半）

## 二、高级修饰符（Modifiers）

以下修饰符可叠加在基础模式之后，构建复合检索策略。

### 1. 时间感知检索 `::Time`

- **语法**：`[[角色日记本::Time]]`
- **功能**：激活自然语言时间解析器，智能识别用户 query 中的时间描述，执行**时间-语义双路召回**。
- **工作机制**：
  1. 解析用户输入中的时间表达（如"上周"、"三个月前"、"2024年5月"）
  2. 支持**多时间点查询**（如"上周和三个月前都聊了什么"）
  3. 双路平衡召回：**语义路占 60%**，**时间路占 40%**
  4. 时间路通过扫描日记文件首行日期匹配时间范围，再计算语义相关性排序
  5. 结果自动去重并合并输出
- **支持的时间表达式**：今天、昨天、前天、本周、上周、本月、上个月、月初、N天前、N周前、N个月前等（详见 `timeExpressions.config.js`）

---

### 2. 语义组增强检索 `::Group`

- **语法**：`[[角色日记本::Group]]`
- **功能**：激活语义组管理器，将查询向量与预定义词组的"组向量"进行加权融合，生成增强查询向量。
- **工作机制**：
  1. 检测用户 query 是否命中 `semantic_groups.json` 中预设的语义组关键词网络
  2. 计算激活强度 = 命中词数 / 组内总词数
  3. 将原始查询向量与激活的组向量做加权平均，生成增强向量
  4. 使用增强向量执行检索
- **适用场景**：逻辑串联、事件线/关系树检索、黑话/梗检索、弥补向量空间中的概念距离缺陷
- **组合示例**：`[[角色日记本:1.5::Group]]`

---

### 3. Rerank 精排 `::Rerank`

- **语法**：
  - `[[角色日记本::Rerank]]` — 标准 Rerank
  - `[[角色日记本::Rerank+0.7]]` — RRF 加权 Rerank（Reranker 占 70% 权重）
- **功能**：先超量获取候选结果，再调用外部 Rerank 模型进行语义精排。
- **工作机制**：
  1. 按 `RerankMultiplier`（默认 2.0）超量召回候选片段
  2. 将用户问题与候选片段打包发送至外部 Rerank 服务（配置项：`RerankUrl` / `RerankApi` / `RerankModel`）
  3. Rerank 模型给出精确语义相关性分数
  4. 按分数重新排序并截取 Top-K
  5. `::Rerank+` 模式使用 RRF（Reciprocal Rank Fusion）融合向量分数与 Rerank 分数，α 可配置（默认 0.5）
- **组合示例**：`[[小克日记本:1.2::Time::Group::Rerank]]`

---

### 4. 时间衰减评分 `::TimeDecay`

- **语法**：`[[角色日记本::TimeDecay[halfLife]/[minScore]/[whitelistTags]]]`
- **示例**：`[[角色日记本::TimeDecay30/0.5/box归档]]`
- **功能**：对检索结果按时间距离施加指数衰减，越久远的内容分数越低。
- **参数**：
  - `halfLife`：半衰期天数（如 30 表示 30 天前分数减半）
  - `minScore`：衰减后最低保留分数
  - `whitelistTags`：仅对指定标签的内容生效（可选，逗号分隔）
- **公式**：`newScore = originalScore × 0.5^(diffDays / halfLife)`

---

### 5. TagMemo / 测地线重排 `::TagMemo`

- **语法**：
  - `[[角色日记本::TagMemo]]` — 动态权重 Tag 匹配（LightMemo 残差金字塔感应）
  - `[[角色日记本::TagMemo0.3]]` — 显式指定 Tag 权重 0.3
  - `[[角色日记本::TagMemo+]]` — TagMemo + 测地线重排（Geodesic Rerank）
  - `[[角色日记本::TagMemo+0.3]]` — 权重 0.3 + 测地线重排
- **功能**：
  - 利用 `applyTagBoost` 从查询向量残差金字塔中感应语义 Tag，对匹配 Tag 的片段进行加权 Boost
  - `+` 变体额外激活测地线重排，通过 `KnowledgeBaseManager.geodesicRerank` 配置控制（默认 α=0.3, minSamples=4）
- **注意**：可配合 `ghostTags`（幽灵节点）强制注入特定 Tag

---

### 6. 截断阈值 `::Truncate`

- **语法**：`[[角色日记本::Truncate0.5]]`
- **功能**：在检索完成后，过滤掉分数低于阈值的片段。
- **工作机制**：`rerank_score ?? score` 与阈值比较，低于阈值的结果被剔除；若全部剔除则返回空。

---

### 7. AIMemo（AI 驱动记忆召回）`::AIMemo`

- **语法**：
  - `[[角色日记本::AIMemo]]`
  - `[[角色日记本::AIMemo:PresetName]]`
- **前置条件**：System Prompt 中必须包含许可证标记 `[[AIMemo=True]]`
- **功能**：将检索到的候选片段批量发送给外部 AI 模型，由 AI 自行判断、总结并输出最相关的记忆内容。
- **工作机制**：
  1. 先进行常规向量检索获取候选池
  2. 按 `AIMemoBatch`（默认 5）和 Token 上限分 Batch
  3. 调用 `AIMemoUrl` 配置的模型进行批量推理
  4. 支持加载 `MoreAIMemoPresets/*.json` 预设以自定义模型与提示词
- **配置项**：`AIMemoModel`、`AIMemoUrl`、`AIMemoApi`、`AIMemoBatch`、`AIMemoMaxTokensPerBatch`

---

### 8. 角色阀门 `::RoleValve`

- **语法**：`[[角色日记本::RoleValve(@User>=2&@Assistant<5)]]`
- **功能**：基于当前上下文中各角色消息数量进行条件判断，**不满足条件时直接阻断检索**。
- **支持逻辑**：
  - 比较运算符：`<`、`>`、`<=`、`>=`、`=`
  - 逻辑组合：`&`（AND）、`|`（OR）
  - 角色名：`@User`、`@Assistant`、`@System`
- **示例**：`@User>=2&@Assistant<5` 表示用户消息数 ≥2 且 AI 消息数 <5 时才允许召回

---

### 9. Base64 附件提取 `::Base64Memo`

- **语法**：`[[角色日记本::Base64Memo]]`
- **功能**：从召回的文本片段中提取 Base64 附件链接，并收集到附件列表中供下游使用。

---

## 三、多日记本聚合检索

- **语法**：`《《日记本1|日记本2|日记本3:1.5》》`
- **功能**：同时从多个日记本中并行检索，结果聚合去重后返回。
- **参数**：
  - `|` 分隔多个日记本名称
  - `:1.5` 为可选的动态 K 乘数
- **配置项**：`aggregateTemperature`、`aggregateMinK`

---

## 四、元思考链（Meta Thinking）

- **语法**：`[[VCP元思考:chainName::Modifier]]`
- **功能**：执行递归向量推理链，按 `meta_thinking_chains.json` 中定义的链式结构进行多层检索与推理。
- **支持修饰符**：`::Group`、`::Auto`
- **实现文件**：`MetaThinkingManager.js`

---

## 五、DeepMemo 三重混合检索（历史对话检索）

`DeepMemo` 是专为历史聊天记录设计的块级检索引擎，采用三重流水线架构：

| 层级 | 算法 | 作用 |
|------|------|------|
| 第一层 | **Fuse.js 模糊搜索** | 全文本模糊召回，容错拼写错误，保证检索广度 |
| 第二层 | **BM25 关键词加权** | 根据关键词稀有度和频率重新排序，擅长定位含特定术语的对话 |
| 第三层 | **Reranker 语义精排** | 使用外部 Rerank 模型理解查询意图，输出最终精确排序 |

---

## 六、内部辅助召回机制

| 机制 | 说明 |
|------|------|
| **Shotgun Query** | 利用最近 3 段历史上下文向量进行衰减聚合检索（衰减因子 0.85），扩展 query 语义覆盖 |
| **上下文去重** | 通过 `contextDiaryPrefixes` 集合检测已注入上下文的日记前缀，避免重复召回相同内容 |
| **幽灵节点（Ghost Tags）** | 外部注入的强制 Tag，可绕过残差金字塔感应，直接参与 TagBoost 加权 |
| **LRU 缓存** | 检索结果带 TTL 缓存，重复查询直接命中，降低向量计算开销 |
| **FoldingStore** | SQLite 持久化存储上下文向量哈希，支持长对话的上下文折叠与回溯 |

---

## 七、自学习系统

| 系统 | 功能 |
|------|------|
| **RAG 寻道自学习** | 根据用户交互（采纳/忽略结果）动态优化检索算法与路径权重 |
| **Tag 权重自学习** | 根据查询频率自动缓慢调整日记本关联 Tag 的权重 |
| **词元组捕网自学习** | 监控查询习惯，自动建议将新概念集、逻辑串、事件关联词汇纳入语义组网络 |

## 八、语法组合规则速查

### 组合优先级与约束

1. `::Time` 与 `::Group` 默认可同时启用（`allowTimeAndGroup = true`）
2. `::Rerank` / `::Rerank+` 可与任何修饰符叠加
3. `::TagMemo` 与 `::Group` 可叠加，增强向量同时参与 TagBoost
4. `::Truncate` 总是最后执行，用于后过滤
5. `::AIMemo` 需要许可证 `[[AIMemo=True]]`，且通常作为最后一层推理叠加
6. `::RoleValve` 在检索流程最前端执行，条件不满足直接返回空

### 完整组合示例

```text
[[小克日记本:1.2::Time::Group::TagMemo+0.3::Rerank+0.7::Truncate0.4]]
```

含义：
- 日记本：小克日记本
- K 值乘数：1.2
- 时间感知 + 语义组增强
- TagMemo 权重 0.3，带测地线重排
- RRF 加权 Rerank（α=0.7）
- 最终截断阈值 0.4
